# Peregrine 桌面 UI 设计提案 — V2 皮肤

> 版本: v1.0-draft · 日期: 2026-09-16 · 状态: 三轮实施完成（U1 commit 9302e1d 前身、U2 9302e1d、U3 f56fd0d，验证记录 docs/reviews/ui-U2-verify.md / ui-U3-verify.md），待 R2 独立评审
> 输入: 知名下载软件 UI 调研（ABDM / Motrix / IDM / AriaNg）+ 开源设计系统（Linear Design System、shadcn-svelte/Bits UI 生态）
> 目标（用户原话）: **高级、精美、现代**，且**符合用户直觉和第一性原理**
> 作用域: `apps/desktop`（Svelte 5 + Tauri 2 webview），不动 daemon/协议

## 1. 现状盘点（为什么必须重做）

| 维度 | 现状 | 问题 |
| --- | --- | --- |
| 布局 | 860px 单栏，`App.svelte` 197 行直排所有区块 | 无导航层级；任务>10 个时头部控制区被推走；860px 在 1440p+ 屏幕上利用率 <50% |
| 视觉 | ~100 行 CSS 变量（OKLCH 色板+亮暗双主题已建）+ 组件内散落样式 | 有色彩系统雏形，但无间距/字号/边框层级规范，视觉密度低 |
| 组件 | 4 个组件 502 行（App / TaskRow / AddDialog / SegmentPanel） | TaskRow 承载动作按钮+进度+状态全在一行，信息过载 |
| 依赖 | 零运行时依赖（仅 @tauri-apps/api） | 无组件库——dialog/dropdown/tooltip 等交互原语全靠手写 |
| 交互 | 无键盘快捷键、无右键菜单、无命令面板、无筛选 | power-user 体验为零；与「MCP/Agent 一等公民」的调性不符 |

**结论**: 色彩变量层可保留（已 OKLCH、已双主题），布局/组件/交互三层全部重做。

## 2. 第一性原理：下载器 UI 的本质是什么？

剥掉所有装饰，下载管理器只做三件事：

1. **看管道** —— 回答"现在多快？还剩多久？卡了没有？"（吞吐监控）
2. **管队列** —— 回答"我有哪些任务？谁先谁后？暂停/恢复/重试哪个？"（队列调度）
3. **查异常** —— 回答"为什么失败？从哪断的？能不能救回来？"（诊断）

由此推导 UI 的三条铁律：

- **速度是心跳**：全局速度必须永远可见（缩到托盘也要在标题/托盘 tooltip 里），任何时刻一眼可得。
- **任务是主体**：屏幕像素大头永远给任务列表；控制区（限速/连接状态）是配角，占比 ≤20%。
- **异常可解释**：错误不是红色字符串，是"原因 + 建议动作"（如 `416 Range Not Satisfiable → 已自动重置分段从零重试`）。

**直觉性**来自三点：分层与用户心智一致（看→管→查）；操作就近（动作出现在对象旁边：悬停行、右键菜单）；破坏性操作可撤销优于确认弹窗。

## 3. 竞品样式调研结论

### 3.1 AB Download Manager（17.9K★，Kotlin Compose，最值得抄的布局）

- **三区结构**：左侧栏分类过滤（Video/Audio/Document/Compressed/…按 MIME 自动归类）+ 顶部工具栏（New/Resume/Pause/Delete/Settings）+ 主区下载列表（表格：文件名/大小/进度/速度/状态/剩余时间）。
- **队列（Queue）是一等公民**：可建多个队列，每队列独立并发数与限速，一键 Start/Stop 整队列。
- **双击完成项 = 打开文件**；Ctrl+F 页内搜索；右键全量上下文菜单。
- **多主题**：Dark/Light/Black（纯黑 OLED）+ 强调色可选。
- 教训：表格列宽不可自定义、状态列文字占太宽——我们改进。

### 3.2 Motrix / Motrix Next（55K★ 原版已死；Next 是 Tauri 2 + Vue 3 社区重写）

- 布局与 ABDM 同构：侧栏任务分类 + 工具栏 + 列表，说明**该范式是品类共识**。
- 视觉更圆润（卡片式任务行、圆角进度条），观感友好但信息密度低——作为反例参考。

### 3.3 IDM（对标基准，UI 老化的教训）

- 树形分类目录 + 双面板（分类列表 + 任务列表）+ 顶部图形工具栏（大图标）。
- **糟粕**：30 年不变的大图标工具栏、五彩分类树、密集对话框——"上世纪 Windows 软件"观感的来源。**精华**：分类即过滤的心智、主窗口极致的列表密度。

### 3.4 AriaNg（aria2 的事实标准 Web 面板）

- 顶部全局统计条（速度/任务数实时跳动）+ 侧栏分类 + 表格。
- 教训：Angular 时代的通用后台面板感——功能全但"管理系统"味重，缺乏品牌温度。**我们要它的全局统计条，不要它的后台感**。

### 3.5 形态学综合

| 品类共识（必须遵守的直觉） | 我们的机会（差异化） |
| --- | --- |
| 侧栏分类过滤 | 自动分类 + **状态过滤**（失败/需关注）合二为一 |
| 顶部工具栏 | 收窄为紧凑工具条，动作就近化（行内+右键）后只留 New/Search/Settings |
| 表格式任务列表 | Linear 式**平铺行网格**：sharp edges、1px 边框分层、行内微图表（分段条） |
| 双击打开文件 | ✅ 直接采纳 + 右键"打开所在目录" |
| 队列并发/限速 | 保留全局层（v2.1 再做多队列） |

## 4. 设计语言：Linear 系（为什么是它）

「高级、精美、现代」在 2026 年的开源标杆答案是 **Linear 风格**（Linear.app 的设计系统被广泛逆向整理为开源参考）。采纳其核心法则：

### 4.1 色彩（已有基础，升级规则）

- **深色优先**：dark 为默认主题，light 为二等公民（都要能用，但打磨重心在 dark）。
- **极度色彩克制**：界面近乎单色（黑/白/灰阶），颜色只出现在**状态语义**处——绿色=下载中/健康、琥珀=暂停/降速、红=错误/危险、强调色=主操作/选中/focus ring。无装饰性用色。
- **OKLCH 色彩空间**（现状已用 ✅）：感知均匀，亮暗主题间色彩映射有数学保证。
- **3 变量主题**：base（背景阶）/ accent（强调）/ contrast（文本强度）——现状 12 个变量收敛为主题生成参数，双主题自动成对。

### 4.2 表面与结构

- **数据面 sharp edges**：任务列表、统计面板、侧栏一律 `border-radius: 0`，像 Bloomberg 终端/IDE，不像卡片 SaaS。圆角只给**浮层**：对话框、下拉、命令面板、tooltip（6-8px + 阴影，"浮起来"的物理暗示）。
- **平铺网格**：面板间零 gap、零 padding，1px 边框线分割（三级边框透明度：强=区块边界 / 默认=控件 / 弱=行分隔）。每一像素都是内容空间。
- **禁卡片嵌套**：不允许 `.card > .card-body` 式包裹——层级用背景色阶（bg-primary→secondary→tertiary）+ 边框表达。这是"高级感"与"廉价感"的分水岭。
- **禁装饰性阴影**：阴影 = 浮层专属语义。数据面区分区域只用背景色阶或 1px 边框。

### 4.3 字体与排版

- **Inter**（正文/界面）+ **等宽字体**（所有数据值：速度、字节数、ETA、任务 id、分段偏移）——"这是数据"的明确信号。
- 层级用**字重与字号**表达，不用颜色和装饰。数字用 `tabular-nums` 防跳动（速度实时刷新时宽度不抖）。

### 4.4 交互与速度

- **100ms 法则**：UI 先变、后确认（乐观更新）。暂停点击即灰、失败静默回滚 + 内联提示。
- **键盘一等公民**：空格=暂停/恢复选中、Del=移除、Cmd/Ctrl+N=新建、`/`=搜索、`?`=快捷键速查。悬停元素数秒后浮现快捷键提示（非侵入式教学）。
- **命令面板（Cmd/Ctrl+K）**：模糊搜索一切动作/任务——与"MCP/Agent 一等公民"的项目调性互为表里（本地用户也是自己的 agent）。
- **右键上下文菜单全覆盖**：暂停/恢复/重试/复制 URL/打开文件/打开目录/移除。
- **撤销优于确认**：移除任务直接执行 + 5s undo toast，不弹"确定吗"。

### 4.5 动效

- ~200ms 缓动微交互（进度条平滑推进、状态 pill 切换），**永不阻塞**、永不为装饰存在。动画只表达状态变化。

## 5. 信息架构与布局提案

```
┌─────────┬──────────────────────────────────────────────┐
│         │  ⌘K 搜索/命令 · 连接徽标 · New · Settings      │ ←48px 工具栏
│  侧栏    ├──────────────────────────────────────────────┤
│  192px   │  ↓ 12.4 MB/s   ↑ 0 B/s   3 active · 1 failed │ ←40px 全局状态条
│         ├──────────────────────────────────────────────┤
│ 全部(12) │  ┌ 名称 ────── 大小 ── 速度 ─ ETA ─ 状态 ┐   │
│ 下载中 3 │  │ ▸ ubuntu.iso    4.2GB  12.4  5:12  ⬇   │   │
│ 已完成 8 │  │   ▓▓▓▓▓▓▓░░░░ 62%  · 分段 8/16 ·     │   │ ← 任务行
│ 失败 1 ⚠ │  │   点选展开详情（SegmentPanel 内嵌）     │   │
│         │  └───────────────────────────────────────┘   │
│ ── 分类  │                                              │
│ 视频 5   │         （主区 = 平铺网格，无卡片 gap）        │
│ 文档 4   │                                              │
│ 压缩包 3 │                                              │
│ ── 其他  │                                              │
│ 限速 🐢  │                                              │
└─────────┴──────────────────────────────────────────────┘
```

- **侧栏（192px）**：状态过滤（全部/下载中/已完成/失败）+ 自动分类（按 MIME）+ 全局限速开关（预设+自定义）。分组计数徽标。可折叠到 48px 图标条。
- **全局状态条（40px）**：聚合速度（↓↑ tabular-nums 等宽跳动）、活动/失败计数。**这是"看管道"的常驻锚点**。
- **任务列表（主区）**：每行=文件名/大小/速度/ETA/状态 pill + 行内分段进度微条；选中行下嵌展开 SegmentPanel（连接级分段视图）；悬停浮出快捷动作（暂停/恢复/重试/移除）。
- **空状态**：不是 "No tasks"——居中图标 + 友好文案 + 拖拽 URL 到窗口即可添加的提示（拖放 = 第一添加入口）。
- **断连态**：全局状态条整条变琥珀 + "守护进程已断开，重连中…"，列表冻结但保留（不清空）。

## 6. 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | **Svelte 5（现状）+ Runes** | 已在用，$state/$derived 与乐观更新天然契合 |
| 样式 | **Tailwind CSS v4** | 2026 现役标准（CSS-first 配置，OKLCH 原生支持）；设计 token（间距/字号/边框三级）直接落 utility，杜绝散落样式 |
| 交互原语 | **Bits UI**（少量）+ 手绘 | dialog/dropdown-menu/context-menu/tooltip/tooltip 用 Bits UI（无样式、行为正确、可访问性内置，93 万周下载）；TaskRow/SegmentPanel/速度表等强定制业务件手绘——框架帮不上 |
| 组件范式 | 参考 **shadcn-svelte**（非直接引入） | 借其"源码归你"思想：需要的模式抄进 repo 改造成 Linear 风，不背依赖 |
| 图标 | **lucide-svelte** | 与 Bits/shadcn 同生态，1kb 级按需 |
| 不引入 | 完整 shadcn-svelte CLI / Melt UI（已被 Bits 取代）/ 任何 chart 库 | 分段条是纯 div/CSS；速度 sparkline 用 SVG polyline 20 行手写 |

**依赖增量**: tailwindcss + @tailwindcss/vite + bits-ui + lucide-svelte ≈ 4 个包，桌面 app 无运行时顾虑（构建期注入）。

**明确不做的**: 动效库、状态管理库（store.svelte.ts 的 runes store 已足够）、CSS-in-JS。

## 7. 实施计划（三轮，沿用 R1→R2→R3 流程）

> 实施状态：三轮全部完成并通过真机验证（详见 docs/reviews/ui-U2-verify.md、ui-U3-verify.md）。

### 轮 U1 — 骨架与设计 token（布局重构）

- Tailwind 4 接入 + `@theme` 定义 token（色板迁移现有 OKLCH 变量 / 间距 4px 基 / 字号阶 / 边框三级透明度）
- 倒 L 骨架：侧栏 + 工具栏 + 全局状态条 + 主区容器（sharp edges 平铺网格）
- 状态过滤 + 分类过滤（store 层加 filter 派生）
- 验收：1280×800 无滚动可见 10+ 任务行；亮暗双主题切换；现有全部功能不回退

### 轮 U2 — 任务行与详情（信息密度）

- TaskRow 重构：列对齐网格 + tabular-nums + 状态 pill + 悬停动作 + 选中态
- SegmentPanel 内嵌展开（选中行下推挤列表）+ 连接级微条
- 拖放 URL 添加 + 空状态 + 断连冻结态
- 双击完成项打开文件（Tauri shell opener）+ 右键菜单（Bits context-menu）
- 验收：信息密度对标 ABDM；键盘 Tab 导航全可达

### 轮 U3 — 精修与键盘层（高级感）

- Cmd+K 命令面板（动作+任务模糊搜索，`/` 聚焦）
- 快捷键全集（空格/Del/Cmd+N/`?`速查面板）+ 悬停快捷键提示
- 乐观更新改造（操作先变后确认，失败回滚 + 内联提示）+ undo toast（移除任务）
- 动效精修（200ms 缓动、进度条平滑）+ B39 一并解决（操作失败 toast/banner）
- 验收：R2 独立审查按本提案 §4 逐条核对（sharp edges/色彩克制/边框层级/100ms）

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Tailwind 4 + Vite 8 + Svelte 5 组合坑 | 轮 U1 第一步先在独立分支跑通最小骨架再迁移 |
| 平铺网格在浅色主题下显得"糙" | 浅色主题边框透明度单独调（contrast 变量本来就要分主题） |
| 信息密度 vs 可读性平衡 | ABDM 列宽教训：名称列弹性伸缩，数据列定宽右对齐 |
| 键盘层与 Tauri webview 焦点冲突 | U3 首日验证 Tauri 2 全局快捷键 API 边界，不行就窗口级 |
