## 本轮教训

1. **不可本机编译的代码 ≠ 不可审查**：R2 任务书给出 registry 缓存路径 +
   逐 API 核对清单，产出了比「跑一次 CI」更细的错误定位（P0 的 From<String>
   陷阱是 CI 红了也看不出根因的类型坑）。以后凡 CI-only 交付物，默认派
   registry-级静态审查。
2. **框架魔法的默认 id 冲突**：config 声明式托盘与代码 builder 的 id 命名空间
   是同一个（都默认 "main"）——声明式+命令式混用时 id 冲突是隐形故障源。
   规则：一个资源一个所有者。
3. dotenv 式「顺手配置」（deep-link/deb.depends）在没有对应依赖/需求时是
   负债——删。
