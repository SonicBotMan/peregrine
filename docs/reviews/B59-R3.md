## 教训（R1→R2 漏斗验证）

1. **R1 存疑点① = R2 P1-1**：自查嗅到了 purge_files=false 语义缺口却未追到底就交审。判据：凡「存疑」涉及**数据删除语义**，必须当场追调用链到终点，不带疑点过闸。
2. **「定位器」与「删除行为」必须同生命周期**：侧表条目（locator）的生命周期要绑定数据本体——数据在，locator 在；数据删成，locator 才消。第一版把它挂在 detach（引用计数）上，生命周期错位产生全部三个 P1。
3. **删除目标的最小实体原则**：持久化任何「待删路径」时先问——这个路径下有没有别人的数据？output_folder 是共享资源，永远不进删除目标；只记 torrent 自己的实体。P0-1 是本轮最重的一课：连坐删除是不可逆的用户数据损失。
4. **R2 超时强杀仍有产出**：watchdog SIGTERM 前的证据完整可采纳（发现全、结论缺）。处置文档记 exit 状态并声明「结论部分缺失，发现全采纳」即可，不必重跑。
