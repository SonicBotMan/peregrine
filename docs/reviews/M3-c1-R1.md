# M3-c1 R1 — 限速 UI + Segments 遥测（自查）

范围：crates/{api,server} + apps/desktop/src/lib/{types,daemon,store.svelte,format,TaskRow,SegmentPanel}.ts|svelte + App.svelte + app.css

## 交付清单

- **后端**：`SegmentView{idx,start,end,len,done,frontier,pct}` (api/task.rs)；`Daemon::segments_of(id)` (daemon.rs) —
  wire id →(url,sink)→ engine 行；无 engine 行=单流→`[]`；无任务→`None`；
  `GET /tasks/{id}/segments` (api.rs)。限速端点（`PUT /tasks/{id}/limit`、`GET/PUT /settings`）是 M3-b1 已交付，
  本轮 UI 打通。
- **前端**：types 补 `speed_limit_bps`/`SegmentView`/`Settings`；daemon.ts 加 `segments`/`setTaskLimit`/`getSettings`/`setGlobalLimit`；
  store 加 `setTaskLimit`（daemon 回显完整 Task，成功即真值）/`setGlobalLimit`/`getSettings`；
  TaskRow：chevron 展开详情 + 限速 select（preset off/512k/1M/2M/4M + custom 数字输入）；
  SegmentPanel：1s 轮询 segments 网格 + ETA/平均速度/limit 徽标（$effect 生命周期，alive 标志防晚到写）；
  App header：全局限速 select（bootstrap 读 settings 一次）；format.ts 共享 formatBytes/Bps/ETA + LIMIT_PRESETS；
  app.css 补 detail/seggrid/limit 样式段。

## R1 检查（逐项）

1. **id 空间桥接**：storage::TaskId(i64) ≠ api::TaskId(字符串)。segments_of 走 tm.get→(url,sink)→get_task，不泄漏 i64。
   单元测试覆盖 404/空列表/映射三态 ✓
2. **轮询生命周期**：SegmentPanel 用 $effect cleanup（alive + clearInterval），组件销毁即停；task.id 依赖行复用重臂 ✓
3. **乐观更新**：setTaskLimit 用 daemon 回显的完整 Task 替换行（无回滚窗口）；失败时行未动，select 下一渲染读回旧值 ✓
4. **WS 与轮询竞态**：segments 轮询只写组件局部 $state（遥测面板），不写 store——无竞态面；速度 EMA 仍由 WS progress 驱动 ✓
5. **鉴权**：daemon 是 loopback-only 无鉴权设计（TCP 只绑 127.0.0.1，UDS 0700）——新端点继承同一模型。
   （勘误：本报告早稿误称有「M3-c0 token 层」；核实无此层。开放非环回监听前 auth 是前置条件——BACKLOG。）
6. **多任务同 sink 同 url**：get_task(url,sink) 返回最新行，与 engine (url,sink) 唯一性约束一致 ✓
7. **真实 smoke**（TUNA archlinux iso 1.6GB / 8 段）：GET segments 8 段、idx0 下载中、frontier 正确；
   404 / PUT limit 1048576 / PUT settings 2097152 全对；vite 代理链全通（health、列表含 speed_limit_bps、segments）。
   E2E 截图被环境挡（chromium 缺 libnspr4/libasound 且无 sudo/apt 源不可用，M3-a 时同样）——wire 层验证代替，截图入 BACKLOG。

## 已知限制（BACKLOG 候选）

- segments 面板打开期间 1 QPS/任务轮询（遥测只读 + 廉价 SQLite，接受）
- custom 限速输入无历史记忆（M4 候选）
- 全局限速只在启动时读一次，其他客户端的在线改动不刷新（事件总线只带任务增量，B37 家族）
- 前端无单测（Vitest 未配；M3 验收以 build+wire smoke 为准）
- E2E 截图需系统浏览器依赖（libnspr4/libasound…），环境装好后补

## 决策记录

- **[] vs 404**：单流任务在 engine 表无行——「任务存在→[]（面板显示 single stream）」而非 404：GUI 已列出任务，点开报错是体验断层。
- **不新增 storage 方法**：最初加 get_segments/has_task（i64 键），发现两 id 空间问题后撤销；改走现成 get_task(url,sink)
  （返回值本就带 segments），storage API 面保持最小。
- **segments 走拉取不走事件**：推送会放大 WS 帧频（每段每次 tick）；面板打开才轮询，关了就停，代价与关注点对齐。
