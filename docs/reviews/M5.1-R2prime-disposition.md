## R3 反思

1. **「契约语言」必须逐引擎审计**：MCP 描述、CLI 帮助、REST 语义都写着「purge deletes partial files」，但四个引擎只有三个真删——HTTP 作为主力引擎恰是漏网的那个。接口改对了不等于语义改齐了；跨层审计要以「用户可读的承诺文本」为清单，而不是以 diff 为清单。
2. **超时≠死亡**：背压（慢消费者）和死亡（断连）在网络语义上是两种故障，处置必须分流。把 timeout 当 error 处理是「快速失败」直觉的过度应用——对推送型通道，丢帧保活才是正确默认。
3. **clap 默认值是构建期代码**：`default_value_t = f()` 在每次 Command 构建时执行，panic 无上下文、错误不可捕获。惰性默认（Option + main 解析）是 CLI 工具的标准姿势。
4. **测试金字塔的分工**：e2e 用 fake port 证明「调用串到了」，契约测试用真 port 证明「文件真删了」——单层测试覆盖不了两层断言，本轮 P1-1 的测试缺口正是只做了第一层。
