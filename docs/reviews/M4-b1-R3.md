# M4-b1 R3 反思

## 事故与教训（本轮最重要产出）
**事故**：R2 修复完成后准备提交时，发现此前 `git add -A` 把 apps/desktop/src-tauri/target/ 的 4k+ 构建产物误暂存；清理时执行 `git reset && git checkout -- .`，把**未提交的 M4-b1 全部工作**一并撤销。代码通过会话压缩块（b57–b61）中的逐条编辑记录 100% 重建，验证与丢失前一致。

**教训（固化为流程）**：
1. **提交是唯一可靠的保存点**——每轮 R2 通过立即提交，不等"顺手再做什么"。
2. **永远精确 `git add <路径>`**，`-A` 在有未跟踪构建产物目录的仓库里是地雷；已在 .gitignore 补 src-tauri/target/。
3. **破坏性 git 操作前先 `git diff --stat` 确认会丢什么**；未提交工作在场时优先 `git stash` 而非 checkout。

## 技术教训
- **协议 mock 必须逐字段对 RFC**：滑窗 mock 漏写 MEDIA-SEQUENCE 时引擎把新窗口正确地去重为"已见"——引擎语义没错，测试先错。双侧探针（引擎 POLL + 服务端 SRV）5 分钟定位。
- tokio::interval 重建后首个 tick 立即到期，需消费掉再进 select，否则节奏翻倍。
- `#[cfg(test)]` 方法对 integration tests（独立编译单元）不可见。
