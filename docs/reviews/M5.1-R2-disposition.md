# M5 R2 迟到报告处置 — MCP 契约修复（M5.1）

日期：2026-09-14 · 背景：M5 已提交 792bbba 后 R2 delegate 报告到达（审查期间工作树被并发提交，reviewer 以 792bbba 为准完成）。报告共 2 P0 + 2 P1 + 8 P2，经逐条核实全部属实。本补丁轮在 M4-b2 提交后执行。

## P0（全部修复）

### P0-1 MCP 默认 socket 与 daemon/CLI 不一致 → 默认部署 MCP 全灭

- 现状：`crates/mcp/src/main.rs` 自造 `default_socket()` = `$HOME/.peregrine/daemon.sock`；真实默认 `peregrine_api::transport::socket_path(None)` = `$XDG_RUNTIME_DIR/peregrine/peregrine.sock`（回退 `/tmp/peregrine-<uid>/peregrine.sock`），且 CLI 支持 `PGRG_SOCKET`。
- 修复：删 `default_socket()`，clap default 改调 `transport::socket_path(None)`（含 PGRG_SOCKET 支持）。MCP 与 CLI 完全同源。

### P0-2 remove 的 purge 契约双向失真（破坏性操作）

- 现状：MCP 描述 "purge=false 保留文件"；daemon `remove_task` 无 Query 提取器静默忽略参数；scheduler `remove()` 无条件调用 `port.purge()`（FTP 总删 sink 文件、HLS 总删 .parts 目录）。
- 修复（破坏性操作显式化，安全默认）：
  1. `server/api.rs`：`remove_task` 加 `Query<PurgeQuery>`（serde 默认 false）
  2. `scheduler::remove(id, purge: bool)`：`purge=false` 跳过 `port.purge()`（HTTP resume 行清理语义并入 purge 路径——false 时仅删任务行，不动任何文件/引擎状态？**决策：resume 行随任务行一起删**——它是内部状态不是用户文件，保留会复活幽灵续传（B31 注释本就为此）；engine `purge()` 语义收窄为「删用户文件」）
  3. `cli` remove 加 `--purge` flag（默认 false）
  4. MCP `remove_download` 描述不变（已正确）
  5. 回归测试：remove 默认保留 sink 文件 + purge=true 删除（HTTP/FTP 各一）
