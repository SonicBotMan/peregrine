# M5 R1 自查报告 — MCP 服务器（Agent 原生层）

日期：2026-09-14 · 轮次：M5 开发 → R1 自查（本文档）→ R2 独立审查 → 修复 → R3 反思 → 提交

## 交付范围

PROPOSAL §3.4「Agent 原生」：`crates/mcp` — rmcp 3.3 MCP 服务器，暴露 peregrine daemon。

### 面积

- `src/lib.rs`（~230 行）：`PeregrineMcp` ServerHandler — initialize 描述、tools/resources/subscribe 路由、资源读取（tasks://、task://{id}、settings://）。
- `src/tools.rs`（~290 行）：10 工具目录（add/list/get/pause/resume/remove/set_limit/segments/get_settings/set_global_limit），显式 JSON Schema，单一 `dispatch` 路由。
- `src/events.rs`（~150 行）：daemon WS `/events` → `notifications/resources/updated` 桥；惰性启动、永久重连（500ms→10s 封顶退避）、事件→URI 映射（每个 task 事件失效 `task://{id}` + `tasks://`）。
- `src/main.rs`：stdio（默认）与 `--http` streamable-HTTP 双模式二进制 `peregrine-mcp`。
- `tests/mcp.rs`（5 集成测试）：真 daemon 栈（scheduler+store+bus+UDS+WS）+ rmcp 客户端配对，覆盖工具往返、错误契约、资源、订阅推送。

### 契约决策

- **MCP 层零策略**：每个工具是 daemon REST 的薄代理（queue/throttle/resume 语义全在 scheduler），不复制 v1「第二大脑」教训。
- **两级错误**：daemon 失败（unknown id、daemon down）= tool-level error（`isError:true`，模型可见可修）；仅 unroutable 请求是协议错误。
- **wire = domain**：资源/工具返回 daemon 的 Task JSON，无平行 DTO。
- **settings:// 无推送**：REST 写不走事件总线（事实如此，资源描述里写明）。
