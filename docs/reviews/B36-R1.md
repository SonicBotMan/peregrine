## 自查发现并已修正

1. **[P1·设计缺陷] fresh 单流 upsert 带 total 会被 Route 1 误判为 segmented partial**——首版写点 `upsert_task(url, sink, server_total, etag)`，total=Some(1000) 会让下次同 (url,sink) 的 add 走 `run_with_downgrade`（segmented 路径）。已改为 **total=NULL 的 validator-only row**；segmented 行不受影响（行已存在只刷 etag；segment 会话自己的 upsert 带 total 升级行）。
2. **[P3] 测试文件尾部 `use`**——已挪头部。
3. clippy `await_holding_lock`×2（测试 assert 持锁跨 await）——改为即取即弃表达式。

## 边界推演（无需改动的）

- **healed 递归**：416 自愈重入 run_download_impl 会再写一次 validator，同值幂等，无害。
- **多任务并发同 (url,sink)**：daemon task manager 保证单飞行（既有语义），无写竞争。
- **HLS/FTP**：vstore 仅 engine-http，不受影响。
- **重定向**：写/读键均为 original url（与 segment 行键既有语义一致；post-redirect 键差异是既有行为，非本轮引入）。
- **`from_wire` 形状误判**（非引号非日期 → 当日期发回）：最坏 no-match If-Range → 200 安全重放，注释已声明。
- **store 失败**：读写两侧全部 degrade 为 validator-less resume（今日行为），不炸下载。
